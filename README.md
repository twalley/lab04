## реализация требований

1. рекуррентная задача - число способов подъема по лестнице

- ways_iterative(n) - итеративное решение через цикл
	сложность: O(n) по времени, O(1) по памяти
	хранит только два последних значения

- ways_recursive(n) - рекурсивное решение с мемоизацией
	сложность: O(n) по времени, O(n) по памяти
	использует словарь для запоминания уже посчитанных значений

2. сортировки

- bubble_sort(arr) - квадратичная сортировка пузырьком O(n^2)
	проходит по массиву много раз, меняя соседние элементы
	оптимизация: если за проход не было обменов - выходим раньше

- merge_sort(arr) - эффективная сортировка слиянием O(n log n)
	делит массив пополам, сортирует каждую половину, сливает
	использует принцип "разделяй и властвуй"

3. структура данных стек

Операции:

- push(item) - положить элемент наверх О(1)
- pop() - снять верхний элемент О(1)
- peek() - посмотреть верхний элемент (не снимая) О(1)
- len(stack) - количество элементов О(1)
- bool(stack) - пустой или нет О(1)

4. генераторы наборов

- random_array(n, seed) - случайный массив из n чисел от -1000 до 1000
- sorted_array(n, seed) - отсортированный по возрастанию
- reverse_sorted_array(n, seed) - отсортированный по убыванию
- almost_sorted_array(n, swaps, seed) - почти отсортированный (несколько случайных обменов)
- many_duplicates_array(n, unique, seed) - с большим количеством дубликатов

Все функции поддерживают параметр seed (при одном и том же seed получается одинаковый массив)

5. benchmark

сравнение скорости bubble_sort и merge_sort

- 5 повторов для каждого замера
- размеры: 100, 1000, 10000, 100000, 1000000
- 5 типов массивов: случайные, отсортированные, почти отсортированные,
с дубрикатами
- для каждого запуска используется копия массива
- генерация массива выключена в измеряемое время
- bubble_sort на больших случайных массивах работает очень долго, 
поэтому на размерах 100000 и 1000000 он тестируется только 
на отсортированных массивах (там он быстрый — O(n))
